### Component definition

`import push from "@vllnt/convex-push/convex.config"`: the `default` export,
defined as `defineComponent("push", { env })`. Pass it to `app.use()`. It
mounts four `@convex-dev/workpool` children (`apnsPool`, `fcmPool`,
`webpushPool`, `customPool`) and one `@convex-dev/rate-limiter`
(`rateLimiter`), and registers a daily cron (`push:prune`). The mount name
defaults to `"push"` (`COMPONENT_NAME`); `app.use(push, { name: "other" })`
adds an independent second mount.

### ComponentApi

`import type { ComponentApi } from "@vllnt/convex-push/_generated/component"`:
the type of `components.push` (generated by Convex codegen). Use it to type a
function that takes a mount. Its functions are the component's public
mutations and queries; call them through `Push`.

### Test helper

`import { register } from "@vllnt/convex-push/test"`:
`register(t, name = "push"): void` registers the component, its four
workpools and its rate limiter with a `convex-test` instance under the mount
name `name`. The `default` export is `{ register, schema, modules }`
(`schema` is the component schema, `modules` its `import.meta.glob` map). The
file is TypeScript source and needs Vite's `import.meta.glob`, so run it under
Vitest with the package in `server.deps.inline`.

## Environment variables

Bound at mount with `app.use(push, { env: { NAME: app.env.NAME } })`. All
optional: a provider is on when its required variables are set, otherwise its
deliveries end with `PROVIDER_NOT_CONFIGURED`. Keys are never function
arguments.

| Variable | Provider | Required for it | Value |
|---|---|---|---|
| `APNS_KEY_P8` | APNs | yes, unless the sandbox pair covers every APNs app | Contents of the `.p8` key file (PEM; literal `\n` is accepted) |
| `APNS_KEY_ID` | APNs | with `APNS_KEY_P8` | The key's id |
| `APNS_TEAM_ID` | APNs | yes | Your Apple team id |
| `APNS_SANDBOX_KEY_P8`, `APNS_SANDBOX_KEY_ID` | APNs | no | A key used for `environment: "sandbox"` apps when both are set; otherwise the main key signs for both hosts |
| `FCM_SERVICE_ACCOUNT_JSON` | FCM | yes | The service-account JSON (`project_id`, `client_email`, `private_key`, optional `private_key_id`). Its `token_uri` is ignored: the token exchange always goes to `https://oauth2.googleapis.com/token` |
| `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY` | Web Push | yes | Raw P-256 key pair, base64url (the form `web-push generate-vapid-keys` prints) |
| `VAPID_SUBJECT` | Web Push | yes | `mailto:` or `https:` contact; anything else ends deliveries with `CREDENTIALS_INVALID` |

A key that is set but unusable ends deliveries with `CREDENTIALS_INVALID` at
send time.

## Push

```ts
// convex/pushClient.ts
import { Push } from "@vllnt/convex-push";
import { components, internal } from "./_generated/api";

// The annotation breaks the type cycle through `internal`.
export const push: Push = new Push(components.push, {
  apps: { ios: { platform: "apns", topic: "com.example.app", environment: "production" } },
  providers: { webhook: { send: internal.pushSenders.webhook } },
  onDelivery: internal.pushHooks.onDelivery,
  defaultTtlSeconds: 86_400,
  maxAttempts: 5,
  maxParallelism: 10,
  scrubContent: true,
  retentionMs: 30 * 86_400_000,
});
```

`new Push(component, options)` binds one mount. `component` is
`components.push` (or the name you mounted it under) and stays readable as
`push.component`. The constructor checks nothing; the component checks the
settings on each send.

### PushOptions

| Option | Type | Default | Notes |
|---|---|---|---|
| `apps` | `Record<string, AppConfig>` | required | Your `appRef` names. `{ platform: "apns", topic, environment: "production" \| "sandbox" }` (`topic` is the bundle id, printable ASCII without spaces), `{ platform: "fcm" }`, `{ platform: "webpush" }` or `{ platform: "custom", provider }` |
| `providers` | `Record<string, { send: CustomSender }>` | `{}` | Custom providers by name, each with its host action ([custom sender](#custom-sender)) |
| `onDelivery` | `DeliveryHook` | none | Host mutation scheduled once per finished delivery ([delivery hook](#delivery-hook)) |
| `defaultTtlSeconds` | `number` | `86_400` | Used when a message has no `ttlSeconds`; same 0 to 2,419,200 range |
| `maxAttempts` | `number` | `5` | Attempts per delivery, 1 to 20 |
| `maxParallelism` | `number` | `10` | Sends in flight per provider pool, 1 to 100. Pool-wide: the last live send's value applies to every send on that pool |
| `scrubContent` | `boolean` | `true` | Erase title, body, data and overrides once no delivery of the message is queued |
| `retentionMs` | `number` | `2_592_000_000` (30 days) | Used by `prune`; the daily cron always uses 30 days |

`apps`, `providers`, `onDelivery`, `maxAttempts`, `maxParallelism` and
`scrubContent` travel with every send and are stored per message, so a change
applies to the next send. `register` checks `appRef` against `apps` before
calling the component.

### Context types

- `RunMutationCtx`: any context with `runMutation` (mutation or action).
- `RunQueryCtx`: any context with `runQuery` from a query or mutation.
- `AnyQueryCtx`: `RunQueryCtx` or an action context's `runQuery`.

Methods that write take `RunMutationCtx`; reads take `AnyQueryCtx`. `send` and
`sendBatch` should run in a mutation so the send joins its transaction.

## Methods

### register

`push.register(ctx, { subjectRef, appRef, address, installRef?, locale? })`
→ `Promise<{ deviceId: string; created: boolean }>`. `RegisterArgs` is the
argument type.

- The same address (by SHA-256 of platform and token, endpoint or custom
  address; Web Push keys are left out) updates its row and moves it to
  `subjectRef` if another subject held it.
- Otherwise a known `installRef` for the same `appRef` replaces that row's
  address (token rotation).
- An `invalid` device becomes `active` again. A `disabled` device stays
  disabled unless it moves to another subject.
- `lastSeenAt` is refreshed on every call, so Apple's 410 timestamp can tell a
  later registration apart.
- A Web Push `endpoint` must be `https` on the default port, with no
  credentials, to a public host name: IP literals, a trailing dot, `localhost`
  and private suffixes (`.localhost`, `.local`, `.localdomain`, `.internal`,
  `.intranet`, `.lan`, `.corp`, `.svc`, `.test`, `.arpa`) are refused with
  `INVALID_ADDRESS`. DNS answers are not checked. `p256dh` must decode to 65
  bytes and `auth` to 16.
- Throws `UNKNOWN_APP` (appRef not in `apps`), `PLATFORM_MISMATCH` (address
  does not fit the app), `INVALID_ADDRESS`, `INVALID_ARGUMENT` (a ref over 256
  characters, `locale` over 64).

### unregister

`push.unregister(ctx, { deviceId, subjectRef? } | { address, subjectRef? })`
→ `Promise<{ removed: boolean }>`. Deletes the device and its rate-limit
state. `removed` is `false` when nothing matched or the device belongs to
another `subjectRef`.

### setDeviceStatus

`push.setDeviceStatus(ctx, { deviceId, status: "active" | "disabled", subjectRef? })`
→ `Promise<{ updated: boolean }>`. Pauses or resumes one device and clears its
invalid code. `updated` is `false` for an unknown id or another subject's
device.

### listDevices

`push.listDevices(ctx, { subjectRef, status?, limit? })` →
`Promise<DeviceView[]>`. `limit` defaults to 20, at most 100. The address is
never returned.

### send

`push.send(ctx, message)` →
`Promise<{ messageId: string; deliveries: number; deduplicated: boolean }>`.
`message` is a `SendMessage` (the same type as `SendInput`). `deliveries`
counts every delivery created, including those that end at once.

| Field | Type | Notes |
|---|---|---|
| `to` | `{ subjectRef }` or `{ deviceIds }` | The subject's active devices (the first 100; more logs `message.device_cap`), or 1 to 100 named devices (duplicate, unknown or inactive ids are skipped) |
| `title`, `body` | `string?` | Up to 1024 characters. Neither means a silent push |
| `data` | `Record<string, string \| number \| boolean>?` | Up to 100 keys of 1 to 256 characters; values finite, strings up to 1024 characters. `aps`, `from`, `notification`, `message_type`, `collapse_key`, `google.*`, `gcm.*` are reserved. FCM receives values as strings |
| `collapseKey` | `string?` | 1 to 64 printable ASCII characters. APNs `apns-collapse-id`, FCM `android.collapse_key`, Web Push `Topic` (hashed) and payload `tag`. Default: the message id on APNs and Web Push |
| `ttlSeconds` | `number?` | Integer 0 to 2,419,200; default `defaultTtlSeconds`. 0 means "now or never" (providers get 0; the queue keeps it sendable for 30 seconds) |
| `priority` | `"high" \| "normal"?` | Default `high` for visible, `normal` for silent |
| `badge` | `number?` | Integer 0 to 1,000,000. APNs `aps.badge`, Web Push payload `badge` |
| `sound` | `string?` | Up to 256 characters. APNs `aps.sound`, FCM Android notification `sound` |
| `category` | `string?` | Up to 256 characters. APNs `aps.category`; FCM Android `channel_id` unless `overrides.fcm.channelId` |
| `overrides` | `Overrides?` | `apns: { threadId?, interruptionLevel?, mutableContent?, rawJson? }`, `fcm: { channelId?, rawJson? }`, `webpush: { icon?, url?, rawJson? }` |
| `idempotencyKey` | `string?` | 1 to 256 characters. A second send with the same key returns the first message (`deduplicated: true`) and queues nothing |

Throws `INVALID_ARGUMENT`, `INVALID_DATA`, `INVALID_RAW_JSON` (not a JSON
object, or over 4096 characters) or `PAYLOAD_TOO_LARGE` (a provider's payload
over its limit after `rawJson` is merged, checked only for the platforms the
message reaches). A throw rolls the whole send back.

Some deliveries end at once, without a send: `APP_NOT_CONFIGURED` (the
device's `appRef` is not in `apps`, or no longer matches),
`PROVIDER_NOT_CONFIGURED` (keys or custom sender missing),
`SILENT_NOT_SUPPORTED` (silent Web Push), `APP_PAUSED` (APNs burst breaker
open) and `TTL_EXPIRED` (the per-device fuse would delay the send past
expiry). A device over 60 sends per minute is delayed, not refused.

### sendBatch

`push.sendBatch(ctx, messages)` → one `{ messageId, deliveries, deduplicated }`
per message, in order. Up to 100 messages and up to 100 deliveries in one
transaction (deduplicated messages count zero). Over either limit, or if one
message is refused, it throws and queues nothing; split the batch. Each
delivery makes several nested component calls, and about 150 timed out on a
local backend.

### status

`push.status(ctx, messageId)` → `Promise<MessageStatus | null>`:
`{ messageId, createdAt, expiresAt, scrubbedAt?, deliveries: DeliveryView[] }`
(the first 100 deliveries). Each delivery has `deliveryId`, `deviceId`,
`platform`, `provider?`, `status`, `attempts`, `providerMessageId?`,
`errorCode?`, `httpStatus?`, `nextAttemptAt?`, `sentAt?`, `updatedAt`.
`null` for an unknown or pruned id. Reactive in a query; never returns
content or addresses.

### listBySubject

`push.listBySubject(ctx, { subjectRef, limit? })` →
`Promise<MessageSummary[]>`: the subject's messages sent with
`to: { subjectRef }`, newest first, with `queued`, `sent`, `failed` and
`invalid` counts. `limit` defaults to 20, at most 100.

### cancel

`push.cancel(ctx, messageId)` → `Promise<{ cancelled: number }>`. Ends every
queued delivery as `failed` with `CANCELLED` and runs the hook for each. A job
already running may still send; if its answer says the device is dead, the
device is still marked invalid. An unknown id returns `{ cancelled: 0 }`.

### prune

`push.prune(ctx, { batch? })` → `Promise<{ deleted: number; more: boolean }>`.
Deletes messages older than `retentionMs` that also expired more than a day
ago (so no send job is still on its way), with their deliveries; devices that
are `invalid` and unseen for `retentionMs`; and expired cached tokens. `batch`
(integer 1 to 1,000, default 1,000) bounds the message and delivery rows one
pass deletes; a pass finishes the message it started, looks at the 100 oldest
messages, deletes up to 100 invalid devices and looks at 100 cached tokens.
While there is more it schedules another pass (`more: true`). With
`retentionMs` under 29 days, a message with a long TTL holds back the messages
created after it until it is a day past expiry. The component's daily cron
prunes with the 30-day default.

## Extension contracts

### Custom sender

A custom provider is one host action (`CustomSender`) with
`args: customSendArgs` and `returns: sendResult`, listed in
`providers: { name: { send } }` and used by apps with
`{ platform: "custom", provider: name }` and devices with
`{ platform: "custom", provider: name, address }`.

`CustomSendArgs`: `{ provider, address, title?, body?, data, options:
{ collapseKey?, ttlSeconds?, priority, badge?, sound?, category? }, attempt,
messageId, deliveryId }`. `attempt` starts at 1.

`SendResult`, one of:

- `{ status: "sent", providerMessageId?, httpStatus? }`
- `{ status: "retry", code?, delayMs?, httpStatus? }`
- `{ status: "invalid", code?, httpStatus?, invalidSince? }`
- `{ status: "failed", code?, httpStatus? }`

A throw or timeout counts as `retry` with `SENDER_ERROR`. Any other value
fails the delivery with `SENDER_BAD_RESULT`. A missing code becomes
`INVALID`, `FAILED` or, at the attempt limit, `RETRY_LIMIT`. `delayMs` is
bounded to one second..one day; `providerMessageId` and `code` are stored up
to 256 characters. Every custom provider shares one pool (`customPool`), so a
slow sender holds slots the others could use. Delivery is at least once; use
`deliveryId` as an idempotency key.

### Delivery hook

A host mutation (`DeliveryHook`) with `args: deliveryEvent`, set as
`onDelivery`. `DeliveryEvent`: `{ messageId, deliveryId, deviceId, platform,
provider?, status: "sent" | "failed" | "invalid", errorCode?, at }`. It is
scheduled once per finished delivery, never inline and never on a retry, so a
hook that throws cannot undo the delivery record. It carries no title, body
or data.

## Delivery lifecycle

```text
queued ──► sent
   │  ├──► invalid   (device marked invalid unless it registered after the provider's timestamp)
   │  └──► failed    (final error, attempt limit, expiry, cancel, device moved to another subject)
   └─ retry: queued again at now + delay (Retry-After, or 1 min doubling to 30 min)
```

A retry stops at the attempt limit (keeping the last code, or `RETRY_LIMIT`)
or when the next attempt would land after `expiresAt` (`TTL_EXPIRED`).
Nothing is sent to a device that moved to another subject after the message
was queued (`DEVICE_REASSIGNED`), was deleted (`DEVICE_GONE`), disabled
(`DEVICE_DISABLED`) or marked invalid (`DEVICE_INVALID`). Content is scrubbed
as soon as no delivery is queued: in the same transaction for `send` and
`cancel`, and in a scheduled mutation right after a send job's result is
recorded.

## Provider answers

| Provider | Answer | Delivery |
|---|---|---|
| APNs | 200 | `sent`, `providerMessageId` = `apns-id` |
| APNs | 400/410 `BadDeviceToken`, `DeviceTokenNotForTopic`, `ExpiredToken`, `Unregistered` | `invalid` (410 timestamp kept) |
| APNs | 403 `ExpiredProviderToken` | `retry`, cached JWT dropped |
| APNs | 429, 5xx | `retry` (`Retry-After`, or 15 min on 5xx) |
| FCM | 200 | `sent`, `providerMessageId` = message name |
| FCM | `UNREGISTERED`, 400 `INVALID_ARGUMENT` on `message.token` | `invalid` |
| FCM | 401 | `retry`, cached access token dropped |
| FCM | 429, 5xx | `retry` (`Retry-After`, or 60 s on 429) |
| FCM token exchange | 429, 5xx | `retry` (`TOKEN_EXCHANGE_UNAVAILABLE`) |
| FCM token exchange | other non-200 | `failed` (`CREDENTIALS_INVALID`) |
| Web Push | 2xx | `sent`, `providerMessageId` = `Location` |
| Web Push | 404, 410 | `invalid` (`NOT_FOUND`, `GONE`) |
| Web Push | 413 | `failed` (`PAYLOAD_TOO_LARGE`) |
| Web Push | 401, 403 | `retry` (`HTTP_401`, `HTTP_403`), cached VAPID JWT dropped |
| Web Push | 429, 5xx | `retry` (`HTTP_<status>`, `Retry-After` honoured) |
| Web Push | subscription keys that cannot encrypt | `invalid` (`BAD_SUBSCRIPTION_KEYS`) |
| Any | network error, 15 s timeout | `retry` (`NETWORK_ERROR`, `TIMEOUT`) |
| Any | 3xx | not followed; handled as that provider's other answers |

Other answers end `failed` with the provider's reason (APNs `reason`, FCM
error code or status) or `HTTP_<status>`. `Retry-After` is honoured within
one second..one day. After 20 APNs `BadDeviceToken` or
`DeviceTokenNotForTopic` answers for one `appRef` within a 10-minute window,
that app's later answers of those kinds and its new deliveries end `failed`
with `APP_PAUSED` until the window ends, and the devices are not marked
invalid (this is how a sandbox/production mix-up shows).

## Errors

Thrown as `ConvexError({ code, message })`; `ERROR_CODES` lists them and
`PushErrorCode` is their type. The README table
[Errors and fixes](../README.md#errors-and-fixes) gives the fix for each.

| Code | When |
|---|---|
| `INVALID_ARGUMENT` | A ref, limit, option or setting out of range; `sendBatch` over 100 messages or 100 deliveries; `unregister` without exactly one of `deviceId` and `address` |
| `INVALID_ADDRESS` | A token, endpoint, key or custom address that cannot be right (whitespace, length, not https to a public host, wrong key length) |
| `INVALID_DATA` | Reserved, too many, too long or non-finite `data` |
| `INVALID_RAW_JSON` | `rawJson` is not a JSON object or is over 4096 characters |
| `PAYLOAD_TOO_LARGE` | A provider's payload is over its limit after the merge |
| `UNKNOWN_APP` | `register` with an `appRef` not in `apps` (client) |
| `PLATFORM_MISMATCH` | `register` with an address that does not fit the app (client) |

### Delivery error codes

Written to a delivery's `errorCode` by the component; `DELIVERY_ERROR_CODES`
lists them and `DeliveryErrorCode` is their type. Provider reasons
(`BadDeviceToken`, `UNREGISTERED`, `HTTP_<status>`) are stored as sent.

| Code | When |
|---|---|
| `APP_NOT_CONFIGURED` | The device's `appRef` is not in `apps`, or its platform or provider differs |
| `APP_PAUSED` | The APNs bad-token breaker for that `appRef` is open |
| `BAD_SUBSCRIPTION_KEYS` | Web Push subscription keys cannot encrypt (`invalid`) |
| `CANCELLED` | `cancel`, or the queued job was cancelled |
| `CREDENTIALS_INVALID` | A key in env is set but unusable, or Google refused the token exchange |
| `DEVICE_DISABLED` | The device was disabled after enqueue |
| `DEVICE_GONE` | The device was deleted after enqueue |
| `DEVICE_INVALID` | The device was marked invalid after enqueue |
| `DEVICE_REASSIGNED` | The device moved to another subject after enqueue |
| `FAILED` | A custom sender returned `failed` without a code |
| `GONE` | Web Push 410 (`invalid`) |
| `INVALID` | A custom sender returned `invalid` without a code |
| `NETWORK_ERROR` | The request failed before an answer (retried) |
| `NOT_FOUND` | Web Push 404 (`invalid`) |
| `PAYLOAD_TOO_LARGE` | Web Push 413 |
| `PROVIDER_NOT_CONFIGURED` | Provider keys not set, or no sender for a custom provider |
| `RETRY_LIMIT` | Attempt limit reached without a provider code |
| `SENDER_BAD_RESULT` | A custom sender returned something that is not a `sendResult` |
| `SENDER_ERROR` | A custom sender or the send action threw or timed out (retried) |
| `SILENT_NOT_SUPPORTED` | Silent message to a Web Push device |
| `TIMEOUT` | No provider answer within 15 seconds (retried) |
| `TOKEN_EXCHANGE_UNAVAILABLE` | Google's token endpoint answered 429 or 5xx (retried) |
| `TTL_EXPIRED` | Expired before the send, before the next retry, or before the per-device fuse allows it |

## Security model

- Keys are read from the component's environment inside the send action and
  are never stored, returned or logged.
- Cached provider tokens are sealed with AES-256-GCM. The key comes from HKDF
  over the private key, with the credential fingerprint as `info`; the
  credential and audience are the additional data.
- Queries return no address, token or content. Logs carry ids, platforms,
  statuses and codes only. The only function that reads addresses and content
  is internal (`loadJob`).
- Tests check that after a send (including error and retry paths) no key,
  JWT, access token or message content is left in plaintext in any table or
  scheduled-function argument of the component and its child components.
  Device addresses are stored, since sending needs them.
- Provider requests never follow redirects, so credentials only go to the URL
  given. Web Push endpoints are limited to public https host names (see
  [register](#register)); custom senders fetch whatever address you store, so
  check those in your own sender.
- FCM `rawJson` cannot set `topic` or `condition`: they are removed, so an
  override cannot change who receives the message.
- Stored function handles must have the `function://` form; a plain function
  name is refused. This is a form check, not a security boundary: the host
  passes its own handles and is trusted.
- The component reads no auth. `subjectRef` on `unregister` and
  `setDeviceStatus` guards against bugs in an honest host, not a hostile
  caller; the host decides who may call what.
